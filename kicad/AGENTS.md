# Правила KiCad

## Интерфейс

- У пользователя русский интерфейс KiCad. Названия меню, кнопок и окон писать по-русски; английские названия давать в скобках лишь при нужде.

## 3D-модели

- `docs/KICAD_3D_MODEL_ALIGNMENT.md` — главная инструкция по привязке, правке и проверке 3D-моделей в KiCad. Читать её перед любой задачей с X3D, STEP, FCStd, PLS или BLS.

## Простой поиск

- Если пользователь просит только найти деталь, модель, файл или ссылку, делать один быстрый поиск и остановиться на первом подходящем результате.
- Отвечать кратко: что найдено, есть ли нужный формат и ссылка на источник.
- Не скачивать, не проверять геометрию, не разбирать код плагинов и не сравнивать много источников без прямой просьбы.
- Углублять поиск лишь тогда, когда подходящего результата нет или пользователь просит проверить точность.

## Проверка знаков и футпринтов

- Разбирать только запрошенную часть проекта.
- Не выбирать штатный знак по общему типу детали: сверять число и назначение физических контактов.
- Номера выводов знака должны точно совпадать с номерами площадок футпринта.
- Проверять названия, номера, типы выводов, площадки, их размеры, номера и связи со знаком.
- При ошибке знака не проверять размеры футпринта или STEP без прямого запроса.
- Перед правкой отделять изменения агента от ручных правок пользователя. Ручные правки не отменять и не называть ошибкой без подтверждения.

## Библиотека my_lyb

- Перед правкой сверять подключённый путь библиотеки `my_lyb`.
- Не заменять всю библиотеку вместо одного запрошенного знака.
- После правки проверять, что новый знак виден в нужной библиотеке, связи открываются, а старые знаки не пропали.

## Перенос детали из EasyEDA в my_lyb

- Если пользователь приложил файлы знака, футпринта и 3D-модели из EasyEDA, сразу работать с ними. Не просить ссылку, номер LCSC, иной формат или повторный экспорт.
- Роль каждого файла определять по имени и содержимому. Если нужного файла нет, просить лишь его.
- Данные EasyEDA переводить в родные файлы KiCad; исходники пользователя не менять.
- До правки сверять пути `my_lyb` в таблицах знаков и футпринтов, а также значение `${MY_LYB}`.
- Сверять номера и имена выводов с площадками. Не связывать их по порядку строк или месту на рисунке.
- Добавлять лишь новый знак и один файл футпринта.
- Не запускать поиск в сети и не писать лишние пояснения, если приложенных файлов хватает. Беречь вызовы инструментов и токены.

### Ошибки, которых нельзя повторять

- Не трогать части, которые пользователь уже проверил и назвал верными.
- Не менять исходные файлы, всю библиотеку или лишние детали.

## Системные модели и рабочий порядок

- Все временные файлы, которые создаёт Кодекс, складывать в папку `codexwork` в корне проекта.
- Не создавать ссылки, junction, каталоги-накладки или подмену системных путей.
- Не перечислять в инструкциях готовые модули и их пути.
- В общие `AGENTS.md` и файлы инфраструктуры не записывать названия, статус, очередь, координаты и историю правок конкретных модулей. Хранить там только короткие правила, пригодные для любых деталей; текущее состояние оставлять в текущей задаче.
- При правке плана давать только изменённые пункты, если полный план не запрошен.

## PDF для ЛУТ

- Готовить один лист А4 в книжной ориентации, строго 1:1: две строки и две колонки, то есть два полных комплекта. Слева в каждой строке — медь, справа — надписи.
- Если два исходных PDF уже готовы, сначала проверить их масштаб, отражение и отверстия, затем собрать лист из них. Без нужды заново их не выводить; сохранять выбранный пользователем размер меток отверстий. Уже зеркальную медь повторно не отражать.
- Перед выводом сохранить текущую открытую плату через API KiCad. Брать размеры из её контура Edge.Cuts, а не из прежнего PDF. Плату ради печати не менять.
- Когда готовых PDF нет, выводить два исходных PDF: F.Cu + Edge.Cuts для меди и B.Silkscreen + Edge.Cuts для надписей. B.Cu с навесными проводами в рисунок меди не включать.
- При новом выводе меди явно включать отверстия фактического размера: `--drill-shape-opt 2`, если пользователь не выбрал малые метки. Для надписей задавать `--drill-shape-opt 0`. Не полагаться на сохранённый пункт «Метки отв.» в окне KiCad: скрипт задаёт его сам.
- Для переноса ЛУТ зеркалить F.Cu один раз при сборке листа. B.Silkscreen выводить без дополнительного отражения: штатные надписи этого слоя уже зеркальны при виде сверху. Проверять отражение обоих рисунков перед выдачей.
- Сохранять контур платы. Вокруг каждого рисунка добавлять пунктирную рамку реза в 1 мм от контура: штрих 1 мм, пробел 0,6 мм, толщина линии 0,1 мм.
- Верхняя линия реза — в 5 мм от края листа. Между контурами соседних плат по обеим осям — 5 мм. Две колонки центрировать на листе.
- Использовать `tools/build_lut_pdf.py`. Промежуточные файлы держать в `codexwork`, готовый PDF — в `output/pdf`. Проверять свежесть исходной платы, отверстия, четыре контура, четыре пунктирные рамки, размер А4 и масштаб; затем отрисовать PDF и осмотреть его.
- В инструкции к готовому файлу указывать: печать 100%, без подгонки и без дополнительного зеркального отражения.
