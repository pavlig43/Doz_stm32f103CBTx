# Дозатор: F103 и F030

Общая логика лежит в `app/` и `lib/`. Весь проект CubeMX для каждого МК хранится в своей папке.

```text
app/                         общая логика
lib/                         общие заголовки и модули
  fee/fee.h                  общий интерфейс памяти
  fee/fee.c                  общий модуль памяти
  enc/enc.h                  общий интерфейс энкодера
  enc/enc.c                  общий модуль энкодера
  hx/hx.h, hx/hx.c            один общий модуль HX711
stm32f103/                   проект CubeMX и сборка F103
stm32f030/                   проект CubeMX и сборка F030
CMakeLists.txt               сборка из корня для CLion
CMakePresets.json            профили F103 и F030
```

В `stm32f103/` находятся `.ioc`, `.mxproject`, `Core/`, `Drivers/`, `cmake/`, файл запуска, файл памяти, `CMakeLists.txt` и `CMakePresets.json`. Корень Git, `app/` и `lib/` остаются общими. Старый `build/` в корне не перенесён; новые сборки пишутся в `stm32f103/build/`.

## Сборка F103

Нужны CMake 3.22+, Ninja и Arm GNU Toolchain (`arm-none-eabi-*`) в `PATH`. В CLion работайте в прежнем корне репозитория. Корневой CMake подключает проект выбранного МК; общий код остаётся виден в том же окне. В `.idea/cmake.xml` сохранены профили F103 Debug, F103 Release, F030 Debug и F030 Release для набора инструментов STM32. Общие файлы уже включены в обе цели; добавлять их вручную не нужно. Для командной строки профили называются Debug, Release, F030-Debug и F030-Release. Переключать папки не нужно. Обе платы запускают общий код дозатора.

```powershell
cmake --preset Debug
cmake --build --preset Debug
cmake --preset Release
cmake --build --preset Release
```

При сборке из корня результаты лежат в `stm32f103/build/CLion-Debug` и `stm32f103/build/CLion-Release`; файлы `.elf` — в их подпапке `stm32f103`. Для F030 используются свои каталоги `stm32f030/build/CLion-*`. Каждый проект также можно собирать отдельно его прежними профилями из папки МК. Общие исходники и пути к заголовкам явно заданы в `stm32f103/CMakeLists.txt`. Обе сборки подключают общие `lib/enc/enc.c` и `lib/fee/fee.c`. В блоке `USER CODE` файла `Core/Inc/tim.h` каждой платы задан `ENC_TIMER`: `htim2` для F103 и `htim3` для F030. В `Core/Inc/main.h` задан `EEPROM_START_ADDR`: `0x0800FC00U` для F103 и `0x08003C00U` для F030. Размер страницы FEE — 1 КБ у обеих плат; в файле памяти F030 для кода оставлено 15 КБ.

## CubeMX и общий код

Открывайте `stm32f103/Doz_stm32f103CBTx.ioc` отдельно. При генерации каталог проекта должен быть `stm32f103`, путь к `main.c` — `Core/Src`, инструмент сборки — CMake. Не выбирайте корень репозитория как каталог вывода. `cmake/stm32cubemx/CMakeLists.txt` внутри проекта принадлежит CubeMX; общие файлы подключайте только в проектном `CMakeLists.txt`. Пользовательский код в `Core/` храните в блоках `USER CODE`.

Для штатного CLI CubeMX загружайте перенесённый `.ioc` и сразу запускайте генерацию; отдельная команда `project path` в CubeMX 6.18 добавляет вложенную папку с именем проекта:

```text
config load <полный путь>/stm32f103/Doz_stm32f103CBTx.ioc
project generate
exit
```

Передавайте такой файл команд в CubeMX через `-q`. На изолированной копии проверены генерация и обе сборки: общие файлы, `USER CODE`, CMake и настройки компилятора сохранены. CubeMX объединяет запись начального низкого уровня `Motor_Pin` с остальными выводами GPIOA; поведение не меняется. Ручной комментарий вне `USER CODE` при этом теряется. Исходный `gpio.c` в этом дереве сохранён.

Для F030 уже создан отдельный `stm32f030/stm32f030.ioc`. CubeMX каждого проекта должен писать только в папку своего МК; `app/`, `lib/` и корневой CMake он не должен менять.

Общие модули получают HAL из проектных `main.h`, `tim.h`, `i2c.h`. Обе платы должны дать сигналы `SCK`, `DOUT`, `Motor`, `R`, `G`, `B`, `Enc_But`, дескриптор `hi2c1` для LCD и `htim1` с шагом счётчика 1 мкс для HX711. Выводы F030 выбираются по схеме.

Код дозатора подключён к F030: в `main.c` добавлены запуск модулей и основной цикл. Debug для F030 использует `-Og`, чтобы код вместе с HAL поместился в 15 КБ Flash; сведения для отладки сохранены. Сборки и расход памяти описаны в [инструкции F030](stm32f030/README.md). Работа на плате ещё требует проверки.
