# Дозатор на STM32F030F4P6

Общий код дозатора подключён в проектном `CMakeLists.txt`. В `Core/Src/main.c` добавлены запуск модулей и основной цикл, как у F103. Сборки проходят; работа на плате ещё не проверена.

## Сборка

Из корня репозитория:

```powershell
cmake --preset F030-Debug
cmake --build --preset F030-Debug
cmake --preset F030-Release
cmake --build --preset F030-Release
```

Нужны CMake 3.22+, Ninja и Arm GNU Toolchain в `PATH`. В CLion выберите F030 Debug или F030 Release. Файлы прошивки относительно этой папки:

- `build/CLion-Debug/stm32f030/stm32f030.elf`;
- `build/CLion-Release/stm32f030/stm32f030.elf`.

Для сборки из самой папки `stm32f030` доступны профили Debug и Release; результаты лежат в `build/Debug` и `build/Release`.

Debug использует `-Og` для приложения и HAL, сохраняя `-g3`. Без оптимизации (`-O0`) код не помещается в 15 КБ Flash. Флаг задан в проектном `CMakeLists.txt`; генерируемые файлы CMake не правились. Release использует `-Os`.

## Память

У STM32F030F4P6 — 16 КБ Flash и 4 КБ RAM. В `STM32F030xx_FLASH.ld` коду отданы первые 15 КБ. Последняя страница, `0x08003C00`…`0x08003FFF`, отведена под настройки FEE. Адрес задан в `Core/Inc/main.h` как `EEPROM_START_ADDR`.

Проверено Arm GNU Toolchain 14.3.1:

| Сборка | Flash из 15 360 байт | RAM из 4 096 байт |
| --- | ---: | ---: |
| Debug (`-Og -g3`) | 14 344 | 2 456 |
| Release (`-Os`) | 13 008 | 2 448 |

Расход RAM включает секции данных, запас кучи 512 байт и стека 1 024 байта. Это проверка размещения при сборке; пиковый расход стека на плате ещё не измерен.

По `.map` и ELF загрузочные секции заканчиваются перед `0x08003808` у Debug и перед `0x080032D0` у Release. Обе сборки оставляют страницу FEE свободной. Полное стирание Flash удалит настройки.

## Выводы в текущем проекте CubeMX

| Сигнал | Вывод |
| --- | --- |
| HX711 DOUT | PF0 |
| HX711 SCK | PF1 |
| Мотор, сигнал управления | PA0 |
| RGB R / G / B | PA2 / PA3 / PA4 |
| Кнопка энкодера | PA5, подтяжка вверх |
| Энкодер A / B | PA6 / PA7, TIM3 CH1 / CH2, подтяжки вверх |
| LCD SCL / SDA | PA9 / PA10, I2C1 |

Адрес LCD в общем коде — `0x27` (для HAL — `0x27 << 1`). TIM1 работает с шагом 1 мкс и периодом 65 535 для HX711; `HX_Init()` сам запускает его. Общий энкодер получает TIM3 через `#define ENC_TIMER htim3` в `Core/Inc/tim.h`.

После вызовов CubeMX идут `Motor_Stop()`, `RGB_Stop()`, `FEE_Settings_Init()`, `HX_Init()`, `LCD_Init()`, `Enc_Init()`. В основном цикле — `Enc_Update_Loop()`, `Enc_Button_Loop()`, `App_Loop()`, `LCD_Loop()`.

## Повторная генерация CubeMX

Открывайте `stm32f030.ioc` и пишите результат только в папку `stm32f030`. Включите сохранение блоков `USER CODE`. CubeMX не должен менять общие `app/`, `lib/` и корневой CMake.

Сохраните метки `SCK`, `DOUT`, `Motor`, `R`, `G`, `B`, `Enc_But`, имена `hi2c1`, `htim1`, `htim3` и определения `ENC_TIMER`, `EEPROM_START_ADDR` в блоках `USER CODE`. Исходные уровни мотора, RGB и SCK — низкие.

После генерации проверьте лимит Flash 15 КБ в файле памяти, шаг TIM1 1 мкс и диапазон TIM3 0…65 535. Общие исходники и пути к заголовкам хранятся в проектном `CMakeLists.txt`; не добавляйте их повторно и не меняйте `cmake/stm32cubemx/CMakeLists.txt` вручную.

## Проверка на плате

Осталось прошить F030 и проверить HX711, LCD, энкодер, короткое и долгое нажатия кнопки, мотор, RGB и сохранение настроек после сброса. Сначала убедитесь, что мотор остаётся выключенным при старте. Успешная сборка не подтверждает работу на плате.
