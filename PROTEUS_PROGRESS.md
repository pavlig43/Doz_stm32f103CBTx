### LCD 16×2 с I2C в одной детали

Нашли штатную деталь `JHD-2X16-I2C`, но она не заменяет связку LCD + PCF8574 для текущего драйвера прошивки.

Установили библиотеку TEP с LCD и PCF8574 в одной детали:

- `C:\Program Files (x86)\Labcenter Electronics\Proteus 8 Professional\DATA\LIBRARY\TEPLCD.LIB`
- `C:\Program Files (x86)\Labcenter Electronics\Proteus 8 Professional\DATA\MODELS\TEPLCD.DLL`

В поиске деталей вводить `I2CLCD16X2`; выбранный вариант — `I2CLCD16X2BLUETEP`.

Для прошивки нужен адрес `0x27` и связи PCF8574: P0 → RS, P1 → RW, P2 → E, P3 → подсветка, P4…P7 → D4…D7. При выборе модели сверили эти параметры. Работу экрана с прошивкой ещё надо проверить запуском.

Архив и распакованные файлы лежат в `C:\Users\user\Downloads\Proteus-LCD-I2C-TEP`.

Источник: [LCD Library for Proteus V3.0, TEP](https://www.theengineeringprojects.com/2026/10/lcd-library-for-proteus-v30.html).

## Связи через имена без длинных проводов

Показали режим `TERMINALS` → `DEFAULT`. Две клеммы с одним именем образуют одну электрическую цепь. Так соединяем, например, мотор и сток Q1 через имя `LOAD`.

Длинный провод между ними не нужен. Точка подключения клеммы должна точно совпасть с концом вывода на сетке. Если между ними есть зазор, нужен короткий провод. Надпись рядом с выводом сама по себе его не соединяет.

## Как завершить схему мотора

Ниже — намеченные связи, а не отчёт о готовой схеме. Давать их пользователю небольшими порциями.

### Силовая часть

1. Плюс питания 12 V → один вывод мотора.
2. Второй вывод мотора → `LOAD` → D Q1, № 2.
3. S Q1, № 3 → минус питания мотора. На текущем листе эта цепь называется `GND_INPUT`.
4. Катод D1, сторона с чертой → `12V`.
5. Анод D1 → `LOAD`.

В текущем положении D1 катод справа, анод слева. Диод подключается параллельно мотору.

### Вход и затвор: низкий уровень включает мотор

В `lib\motor\motor.c` проверено: `Motor_Run()` задаёт низкий уровень, `Motor_Stop()` — высокий. Поэтому для этого аналога намечена схема с таким же действием входа.

Выводы PC817 на скриншоте: A № 1 сверху слева, K № 2 снизу слева, C № 4 сверху справа, E № 3 снизу справа.

| Откуда | Куда |
| --- | --- |
| Вход `PWM` от PA9 | R1, 330 Ом |
| Другой конец R1 | A PC817, № 1 |
| K PC817, № 2 | Сигнальная земля `GND` контроллера |
| C PC817, № 4 | Узел `GATE_CTL` |
| E PC817, № 3 | Минус питания мотора, сейчас `GND_INPUT` |
| `12V` | R2, 10 кОм |
| Другой конец R2 | `GATE_CTL` |
| `GATE_CTL` | R3, 100 Ом |
| Другой конец R3 | G Q1, № 1 |

При высоком уровне на `PWM` оптопара открывается и тянет затвор вниз: мотор выключен. При низком уровне оптопара закрыта, R2 поднимает затвор к 12 V: мотор включён.

Название `GND_INPUT` на текущем листе относится к минусу батареи. Не путать его с отдельным входом `GND` оптопары. Если нужно сохранить развязку, не объединять эти цепи общей меткой земли. Перед сборкой входной части проверить, какие сети создают выбранные символы в Proteus.

PC817 и подтяжка 10 кОм выбраны для медленного включения и выключения в этой проверке. Работу на высокой частоте ШИМ не проверяли. При отключённом входе эта схема включает мотор через R2; остановка при обрыве входа здесь не обеспечена.

## Сохранение модуля

Пользователь хочет сгруппировать схему и сохранить блок с пятью выводами. До этого надо завершить связи и проверить пуск и остановку мотора.

В местной справке Proteus нашли два пути:

- Плоский фрагмент схемы можно сохранить как Project Clip (`.PDSCLIP`).
- Для детали с пятью внешними выводами подходит иерархическая схема с внешним файлом `.MOD` и сохранением детали в библиотеку через `Make Device`.

Project Clip не сохраняет содержимое дочерних листов. Нельзя упаковать только внешний блок и считать, что его внутренняя схема тоже попала в клип.
