## Текущее состояние прошивки

- Исходный проект настроен на STM32F103CB, 128 КБ Flash и 20 КБ RAM. Для симуляции выбрана доступная модель C8. Перед загрузкой проверить размещение кода и данных; при нужде сделать отдельную сборку для симуляции.
- ELF: `C:\Users\user\CLionProjects\Doz_stm32f103CBTx\build\Debug\Doz_stm32f103CBTx.elf`. Перед загрузкой пересобрать из текущих исходников.
- Последняя проверка команды сборки Debug в этом чате завершилась успешно: `ninja: no work to do`.
- HSE — 8 МГц, PLL ×9, процессор — 72 МГц. TIM1 настроен на шаг 1 мкс и нужен для чтения HX711. Не путать внешний кварц с частотой процессора в свойствах модели.
- `app/work/work.c` уже упрощён: состояния `WAIT_PUSH`, `DOSING`, `PULSE_PAUSE`, `PULSE_RUN`; двух флагов импульсов больше нет.
- Настройки читаются из `settings_ram` внутри `Dosing_Loop()`. Отдельные статические копии и `Dosing_Init()` убраны.
- `Work_Stop()` выключает мотор и задаёт `WAIT_PUSH`. Его вызывает и достижение веса, и длинное нажатие при выходе в меню.
- Вход в WORK и пуск дозы — два разных коротких нажатия: первое открывает режим, второе запускает дозу.
- **Тарирование перед дозой ещё не добавлено.** `HX_Tare()` существует, но никто её не вызывает. Сейчас она берёт среднее, в котором могут оставаться пробы прошлой дозы.
- Ноль хранится в `tare`; текущий перевод веса: `(average - tare) * 100 / factor`. При калибровке фактор считается как `(raw_1kg - hx_zero) / 10`. Эти формулы согласованы; не заменять одну без другой.
- По умолчанию целевой вес — 3000 г, порог перехода к импульсам — 50 г, длительность импульса — 500 мс. Пауза между импульсами — 500 мс. Коэффициент калибровки по умолчанию нулевой; перед проверкой дозы нужно выполнить калибровку или задать известный фактор для тестового входа.
- Настройки во Flash лежат с `0x0800FC00`, страница 1 КБ. Проверить работу этой области в модели C8; не переносить её молча в основной прошивке.
- `PROJECT_DESCRIPTION.md` отстаёт от кода: там есть старые сведения о пустом рабочем режиме и коэффициенте float. Источник истины — текущие исходники.

### Первая проверка: мотор выключен при старте

В последних правках пользователя удалён `Motor_Stop()` из запуска `main.c`, а `gpio.c` задаёт `Motor_Pin` и `SCK_Pin` вместе в `GPIO_PIN_RESET`. В `motor.c` низкий уровень включает мотор. До запуска дозы `WAIT_PUSH` его не выключает.

Проверить это первым. Для мотора нужен начальный высокий уровень; для SCK HX711 — низкий. Предложить минимальную правку начальных уровней или вернуть остановку при запуске. Не ограничиваться успешной компиляцией.

2. Найти Blue Pill / STM32F103C8. Проверить, что выбран компонент с моделью симуляции.
3. Настроить питание, общий GND, загрузку из Flash, сброс и тактирование по модели. Проверить BOOT0 и HSE, если эти выводы доступны в выбранном компоненте.
4. Пересобрать прошивку, указать ELF в свойстве программы микроконтроллера. Уточнить точное имя поля по открытой версии Proteus.
5. На PA9 подключить логический анализатор. До пуска дозы там должен быть высокий уровень.

Результат этапа: модель загружает прошивку, выполняет основной цикл, мотор остаётся выключенным. Если стоит в `Error_Handler()`, найти причину по отладке и сообщениям Proteus.

## Этап 2. Подключить LCD и органы управления

Текущие соединения:

| Вывод STM32 | Назначение |
| --- | --- |
| PA0 | Энкодер A, TIM2_CH1 |
| PA1 | Энкодер B, TIM2_CH2 |
| PC13 | Кнопка энкодера; нажатие замыкает на GND, есть внутренняя подтяжка вверх |
| PB6 | I2C1 SCL |
| PB7 | I2C1 SDA |
| PA10 | HX711 DOUT |
| PA11 | HX711 PD_SCK |
| PA9 | Мотор: низкий уровень — пуск, высокий — остановка |

1. Подключить LCD 16×2 через PCF8574. Простое прямое подключение параллельного LCD к STM32 не совпадёт с текущим драйвером.
2. Адрес расширителя должен быть **0x27**, как в `lib/lcd/lcd.c`. Для PCF8574 с базовым адресом 0x20 это A0, A1, A2 = 1. У PCF8574A другой диапазон адресов.
3. Связи расширителя с LCD по текущему коду: P0→RS, P1→RW, P2→E, P3→подсветка, P4…P7→D4…D7. Проверить питание, контраст и подтяжки I2C.
4. Добавить энкодер и кнопку. Проверить выбор WORK/SETTINGS, короткое нажатие и выход длинным нажатием. Порог длинного нажатия сейчас 600 мс.

Результат этапа: видно меню, настройки доступны, WORK показывает PUSH. Не переходить к весам с неработающим экраном или кнопкой.

## Этап 3. Подключить HX711 и проверить чтение

1. Добавить модель HX711. DOUT→PA10, PD_SCK→PA11, общий GND и питание по требованиям модели.
2. Подать сигнал веса через LOADCELL, если эта модель доступна и удобна. Иначе задать управляемый дифференциальный сигнал на входе A HX711. Объяснить пользователю, как меняется сигнал и как он соответствует весу; не угадывать масштаб модели.
3. Отдельно запустить два режима RATE: 0 — 10 Гц, уровень DVDD — 80 Гц. Это вход HX711, а не настройка SCK.
4. Проверить интервалы новых отсчётов и импульсы SCK. Считать только успешные `HX_Read()`, а не проходы основного цикла. Между отсчётами при непрерывном чтении ожидаются примерно 100 мс либо 12,5 мс; задержки самой программы могут их увеличить.
5. Выполнить калибровку через меню: пустые весы, затем эталон 1 кг. На первом этапе можно взять известный тестовый фактор, явно указав его происхождение.

Результат этапа: меняется сырой отсчёт, направление верное, коэффициент ненулевой, известная добавка веса даёт нужный вес в граммах.

Паспорт HX711: https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/538/hx711_5F00_english_2D00_1022875.pdf. Он задаёт частоты, но не доказывает, какой режим стоит на физическом модуле пользователя.

## Этап 4. Добавить тарирование без отдельной паузы

Требование пользователя: перед каждой дозой стоит новая пустая тара; её вес не должен входить в вес продукта. Пользователь ставит тару и нажимает кнопку пуска.

Обсуждённый вариант, который ещё надо воплотить и проверить:

1. Читать свежие отсчёты HX711 в `WAIT_PUSH`, чтобы хранить текущий вес пустой тары.
2. По нажатию взять последний свежий сырой отсчёт за ноль. По возможности обработать готовую пробу перед фиксацией нуля.
3. Заполнить этим отсчётом буфер среднего или иначе сбросить его так, чтобы пробы прошлой дозы не влияли на новую.
4. Сразу перейти к подаче. Не добавлять ожидание пяти новых проб после нажатия.
5. Если ещё не получено ни одной пробы, ноль задать нельзя: дождаться первой пробы без блокировки основного цикла. Это условие корректной тары, а не новый таймаут отказа датчика.

Не брать среднее прошлой дозы за новую тару. Опрос в ожидании не должен лишать другие режимы их проб или дважды добавлять один отсчёт в среднее.

Пользователь отверг паузу 3 секунды и ожидание 5 проб после кнопки: при 10 Гц это около полусекунды. Не возвращать эти задержки под другим именем. Отдельно проверять тару, поставленную незадолго до нажатия: последняя проба может ещё относиться к прежней нагрузке. Не обещать точность до проверки.

## Этап 5. Проверить дозу и смену тары

Для первой проверки поставить цель **200 г**. Рост сигнала веса сначала задавать вручную; замыкать модель подачи на сигнал мотора можно позже.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Пуск устройства | Мотор выключен до кнопки |
| Пустая тара 50 г, пуск, добавка 200 г | Доза считается по продукту; суммарная нагрузка в конце около 250 г |
| Новая пустая тара 300 г, пуск, добавка 200 г | Снова 200 г продукта; суммарная нагрузка около 500 г |
| Новая тара после полной предыдущей дозы | Старое среднее не сдвигает ноль |
| Пуск сразу после установки новой тары | Проверен возраст пробы, ноль относится к новой таре |
| Остаток до цели ровно равен stop_before | При текущем условии `>=` ещё идёт непрерывная подача |
| Остаток меньше stop_before | Мотор останавливается, затем идут импульсы с паузами |
| Вес достиг или превысил цель | Мотор выключен, состояние WAIT_PUSH |
| Длинное нажатие при подаче, импульсе или паузе | Мотор выключен, открыто меню |
| Возврат в WORK после отмены | Автоматического продолжения дозы нет |
| Одинаковый сигнал при 10 и 80 Гц | Сравнены задержка чтения, среднего и момент остановки |

Записать заданный сигнал веса и команды PA9 на одной шкале времени. Не выдавать ручную смену веса за модель механики подачи. Даже при идеальной схеме среднее из пяти проб задерживает реакцию на растущий вес.
